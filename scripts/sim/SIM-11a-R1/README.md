## 0. 먼저 — 무엇을 하는 시험인가

**ALB 서브넷에서 `status-svc` 파드로 들어오는 트래픽만** 8분 막습니다. 클러스터 안은 건드리지 않습니다.

재는 것은 **감지 시간 하나**입니다 — 주입부터 CloudWatch 경보가 `ALARM`으로 가기까지(`t2 − t0`). 복구 시간은 재지 않습니다.

🔴 **Chaos Mesh 를 쓰지 않습니다.** 그래서 `sim-13` 브랜치의 네임스페이스 필터, `web` 네임스페이스 주석, 원복 시점과 **무관**하게 돕니다. 원복만 끝나면 바로 들어갈 수 있습니다.

## 1. 🔴 각오하고 들어갈 것 — ALB 준비 게이트

`web` 네임스페이스에 `elbv2.k8s.aws/pod-readiness-gate-inject: enabled` 가 있어 `status-svc` 파드에 **준비 게이트**가 붙어 있습니다(지금 `True`). 게이트는 **ALB 대상이 healthy 해야** 통과합니다.

11a 는 ALB → 파드를 막으니 대상 헬스체크도 실패합니다. **그래서 이렇게 될 수 있습니다.**

| 일어날 수 있는 일 | 판정에서 어떻게 보나 |
|---|---|
| 준비 게이트 조건 → `False` | **예상된 결과** — 중단 사유 아님 |
| 파드 `Ready` → `False` | **예상된 결과** — 중단 사유 아님 |
| 🔴 **Service 엔드포인트 이탈** (엔드포인트는 `Ready` 를 따릅니다) | **예상된 결과** — 클러스터 안 호출자도 끊깁니다 |
| 그로 인해 울리는 클러스터 안 경보 | **실-3에서 제외** |

> 🔴 **중단 기준은 `Ready` 가 아니라 `ContainersReady` 입니다.** 컨테이너가 살아 있고 재시작이 0이면 계속 갑니다. kubelet 준비 프로브는 **노드에서 오고 노드 서브넷은 막지 않으므로** 통과합니다.
>
> LBC(`v3.5.0`)가 이미 `True` 인 게이트를 실제로 `False` 로 되돌리는지는 **확인하지 못했습니다.** 되돌리든 안 되든 위 기준으로 판정하면 됩니다 — 어느 쪽인지 이번에 관측으로 남습니다(관측 4·6).

## 2. 실행 — 여섯 단계

### 0단계 · 사전 공지와 직전 확인

```bash
cd AWS/scripts/sim/SIM-11a-R1
chmod +x 관측.sh
```

1. **Discord `critical`·`warning` 채널에 사전 공지** — "11a 진입점 차단 시험, 8분" (SNS 는 구역 1 구독이 0건이라 공지 대상 아님)
2. 🔴 **직전 확인 3가지** — `./관측.sh before` 가 아래를 찍습니다. **눈으로 보고 기록**하십시오.
   - ① **정책 집행이 켜져 있나** (`aws-node` 의 `nodeagent --enable-network-policy=true`) ← 이게 꺼져 있으면 **주입이 아예 안 걸립니다**(실-1 무효)
   - ② 준비 게이트 조건이 지금 `True` 인가
   - ③ ALB 대상 그룹이 healthy 인가

### 1단계 · 전 상태 (3분)

```bash
./관측.sh before            # 증거/01_전상태.txt 에 쌓입니다
```

외부 200 · 경보 둘 다 OK · `ContainersReady=True` · 엔드포인트 2 · Argo 전부 정상인지 봅니다. **골든 비교도 이때 한 번** 떠 두십시오.

### 2단계 · 🔴 주입 — `t0` 기록

```bash
date -u +"t0 = %Y-%m-%dT%H:%M:%SZ"          # ← 이 값을 적어 두십시오
kubectl apply -f netpol-block-alb.yaml
kubectl -n web get networkpolicy sim-11a-block-alb-ingress
```

`apply` 응답이 돌아온 시각이 **`t0`** 입니다. 초 단위로 적어 주십시오.

### 3단계 · 추적 (8분)

```bash
./관측.sh watch             # 30초 간격 · 증거/03_추적.txt
```

🔴 **첫 외부 실패가 보이면 그 시각이 `t0'`** 입니다. `t0` 와 다를 수 있습니다(정책 적용 지연 · 이미 맺어진 keep-alive 연결이 남음). 둘 다 적습니다.

경보가 `ALARM` 으로 가는 것도 이 화면에 보입니다. **8분이 되면 멈추십시오**(Ctrl-C).

### 4단계 · 해제와 복구 확인

```bash
kubectl delete -f netpol-block-alb.yaml
date -u +"해제 = %Y-%m-%dT%H:%M:%SZ"
./관측.sh snap              # 외부 200 · 경보 OK · 게이트 True 복귀 확인
```

### 5단계 · 🔴 `t1`·`t2` 와 CSV — **측정 당일에**

```bash
./관측.sh after                                                   # 경보 전이 이력 → t2
./관측.sh csv 2026-10-23T00:00:00Z 2026-10-23T01:00:00Z          # 구간은 실제 측정 시각으로
```

🔴 **CSV 는 반드시 그날 뜨십시오.** Route53 헬스체크 지표의 **1분 해상도는 15일만** 남습니다. 지나면 5분 롤업뿐이고 `Minimum` 통계라 분 단위 전이 시각을 못 읽습니다.

### 6단계 · 알림 전수와 판정

- Discord `critical`·`warning` 채널에 **시험과 무관한 경보가 나갔는지** — 0건이 예상입니다(관찰)
- SNS 구독 목록(구역 1은 0건) · Healthchecks.io 상태
- 골든 비교 후 → 전과 대조

## 3. 🔴 중단 — 아무 때나 이 한 줄

```bash
kubectl delete -f netpol-block-alb.yaml
```

| 중단 사유 | 판단 기준 |
|---|---|
| ① | 🔴 **`ContainersReady` 상실 또는 재시작 > 0** — 파드 `Ready`·게이트 `False` 는 **예상이므로 중단 아님** |
| ② | 시험과 무관한 경보가 Discord 로 나감 (`status-svc` 준비·엔드포인트에서 비롯한 것은 제외) |
| ③ | 다른 네임스페이스나 **구역 2**에 영향이 보임 |
| ④ | **차단 8분 상한 도달** — 경보가 `ALARM` 으로 안 갔어도 해제하고 실-2 로 기록 |

주입이 `web` 네임스페이스의 `app=status-svc` 하나만 고르고 있으므로, 지울 때도 그 자원 하나만 사라집니다. **Argo 가 관리하는 자원이 아니라 selfHeal 과 무관**합니다.
