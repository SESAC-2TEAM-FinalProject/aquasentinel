# 런북 — 도쿄 DR 러너 깨우기 (서울이 빠졌을 때)

- 대상: `terraform/tokyo/runner` 가 만드는 GitLab Runner EC2 1대 + GitLab 쪽 Pause 해제
- 작성 2026-10-27 · A(원주)
- 근거: 2026-10-27 실측(`.gitlab-ci.yml:63` · `global/runner/main.tf` · 도쿄 기본 VPC · 서울 EKS 엔드포인트)
- **이 문서에서 운영을 바꾸는 곳은 2장과 4장뿐입니다.** 나머지는 읽기입니다

> **한 줄** — 도쿄를 세우는 수단(`tokyo/rebuild/*`)이 **서울에 사는 러너 1대**에 걸려 있었습니다. 공유 러너가 꺼져 있어서 그 러너가 빠지면 잡이 영원히 대기합니다. 도쿄에 같은 태그의 러너를 **Pause 로** 하나 더 두고, 재해 때 **Pause 만 풀어** 그 순환을 끊습니다. 🔴 **평소에 Pause 를 풀어두면 안 됩니다** — 서울 잡을 가로채고 그 잡은 실패합니다.

---

## 0. 왜 이게 필요한가 (2026-10-27 실측)

| 사실 | 근거 |
|---|---|
| 모든 CI 잡이 단일 태그 `eks-self-hosted` 에 묶여 있다 | `.gitlab-ci.yml:63` — 파일 전체에서 `tags:` 는 이 **1곳** |
| **공유 러너가 꺼져 있다** | 같은 줄 주석 — "태그가 없으면 '온라인 러너 없음'으로 대기한다" |
| 그 태그를 가진 러너는 **서울 1대** | `i-0932432c8a07fb90a` · t3.medium · `ap-northeast-2c` · 공개 IP 없음(`10.0.34.50`) |
| 서울 러너는 서울 VPC·서울 state 에 묶여 있다 | `global/runner/main.tf:56`(1-network) · `:68`(2-cluster) · `:180`(vpc_id) · `:276`(서울 사설 서브넷) |

→ **서울 리전이 빠지면 러너도 빠지고, 도쿄를 복구할 수단이 없어집니다.**

## 1. 기준값 — 평소 상태 (읽기)

| 항목 | 평소 값 | 확인 방법 |
|---|---|---|
| 도쿄 러너 EC2 | **running 1대** (ASG `aquasentinel-dev-gitlab-runner-tokyo`, desired=1) | `aws ec2 describe-instances --region ap-northeast-1 --filters 'Name=tag:Name,Values=aquasentinel-dev-gitlab-runner-tokyo' 'Name=instance-state-name,Values=running' --query 'length(Reservations[].Instances[])'` |
| GitLab 러너 상태 | 🔴 **Paused** | GitLab → Settings → CI/CD → Runners |
| 러너 태그 | `eks-self-hosted` (서울과 **같게**) | 같은 화면 |
| 사는 곳 | 도쿄 **기본 VPC** `vpc-0fbdc871b703c5d11`(`172.31.0.0/16`) · 공개 서브넷 3개(`1a`·`1c`·`1d`) | `terraform -chdir=terraform/tokyo/runner output vpc_id` |

🔴 **왜 상시 가동인가** — `desired=0` 으로 두면 0→1 로 올리는 수단이 Terraform 이고, 그 Terraform 을 돌릴 러너가 바로 이 러너입니다(순환 재발). 손으로 `set-desired-capacity` 를 쳐도 되지만 재해 중 런북이 한 줄 늘고 부팅 2~3분이 RTO 에 더해집니다. **상시 가동을 택했습니다**(2026-10-27 결정).

🔴 **왜 도쿄 재구축 VPC(10.1.0.0/16)가 아닌가** — 거기에 두면 도쿄를 내릴 때 러너도 사라집니다. 그런데 이 러너는 도쿄를 **다시 세우기 위해** 살아 있어야 합니다.

## 2. 재해 때 — 깨우기 (🔴 변경)

### 2.1 서울 러너가 정말 죽었는지 먼저 본다

```bash
aws ec2 describe-instances --region ap-northeast-2 \
  --filters 'Name=tag:Name,Values=aquasentinel-dev-gitlab-runner' \
  --query 'Reservations[].Instances[].{ID:InstanceId,State:State.Name}' --output table
```

🔴 **서울 러너가 살아 있는데 도쿄 Pause 를 풀면 안 됩니다.** 둘이 같은 태그라 잡이 양쪽으로 비결정적으로 갈립니다. 무엇이 깨지는지 정확히 적으면:

| 잡 | 도쿄 러너에서 돌면 |
|---|---|
| 이 레포(Terraform) 잡 | **대체로 성공합니다** — AWS 인증은 OIDC 역할(`modules/aws-cicd`)이 하고 러너 위치와 무관하며, 서울 EKS 도 공개 엔드포인트(`0.0.0.0/0`)라 도쿄에서 닿습니다. 문제는 결과가 아니라 **어느 러너가 받았는지 추적이 안 되는 것**입니다 |
| 🔴 **`web`·`api-module` 레포 잡** | **깨집니다.** 그 레포들도 같은 태그 `eks-self-hosted` 를 씁니다(`.gitlab-ci.yml:3-4`). Kaniko 가 ECR push 인증을 **인스턴스 프로파일**에서 가져오는데, 도쿄 러너 정책은 `arn:aws:ecr:ap-northeast-1:*` 으로 좁혀져 있어 **서울 ECR push 가 AccessDenied** 입니다 |


### 2.2 도쿄 러너가 올라와 있는지 확인

```bash
aws ec2 describe-instances --region ap-northeast-1 \
  --filters 'Name=tag:Name,Values=aquasentinel-dev-gitlab-runner-tokyo' \
            'Name=instance-state-name,Values=running' \
  --query 'Reservations[].Instances[].{ID:InstanceId,AZ:Placement.AvailabilityZone,PubIP:PublicIpAddress}' --output table
```

공개 IP 가 **있어야** 합니다(아웃바운드가 IGW 로 바로 나갑니다 — 도쿄에 NAT 가 없습니다).

올라와 있지 않으면:
```bash
aws autoscaling set-desired-capacity --region ap-northeast-1 \
  --auto-scaling-group-name aquasentinel-dev-gitlab-runner-tokyo --desired-capacity 1
```

### 2.3 GitLab 에서 Pause 해제

GitLab → 프로젝트 **Settings → CI/CD → Runners** → 도쿄 러너 → **Resume**

🔴 여기까지 하면 `.gitlab-ci.yml` 을 **한 줄도 고치지 않고** 잡이 도쿄 러너로 갑니다. 태그를 서울과 같게 둔 이유가 이것입니다.

### 2.4 러너가 잡을 받는지 확인

아무 파이프라인이나 하나 돌려 `validate:tokyo-runner` 가 **pending 에서 running 으로** 넘어가는지 봅니다. 계속 pending 이면 2.3 이 안 먹은 것입니다.

## 5. 하지 않는 것

- **도쿄 러너로 서울 컴포넌트를 apply 하지 않습니다.** 🔴 기술적으로는 될 수 있습니다(서울 EKS 공개 엔드포인트가 열려 있고 인증은 OIDC 역할이 합니다) — 하지만 ECR 권한이 도쿄로 좁혀져 있고(`web`·`api-module` 빌드가 깨집니다) 어느 러너가 돌렸는지 추적이 안 됩니다. **되는 것과 해도 되는 것은 다릅니다.**
- **EIP 를 붙이지 않습니다.** 이 러너는 아웃바운드만 하고(GitLab.com · ECR · EKS 공개 엔드포인트 · SSM) 들어오는 연결이 없습니다. 🔴 단, 나중에 EKS 공개 엔드포인트를 CIDR 로 좁히게 되면 **그때는 EIP 가 필요해집니다**.
- **태그를 다르게 주지 않습니다.** 다른 태그로 주면 `.gitlab-ci.yml` 의 모든 잡에 태그를 추가해야 하고, 재해 중에 CI 파일을 고치는 일이 생깁니다.

| 무엇 | 왜 |
|---|---|
| 🔴 GitLab UI 에서 러너 **생성**(태그 `eks-self-hosted` · **Paused** 체크) | 최신 GitLab 의 러너 인증 토큰은 "러너를 먼저 만들고" 받는 것이라 태그·Pause 가 토큰에 묶여 있습니다. `--tag-list` 로 줄 수 없습니다 |
| 🔴 그 토큰을 **도쿄 리전** Secrets Manager 에 `aquasentinel-dr-tokyo-gitlab-runner-token` 으로 넣기 | 평문을 git·user-data 에 남기지 않기 위함(다른 모든 시크릿과 같은 수동 패턴). 이 컴포넌트가 만들지 않습니다 |
| 최초 `apply` 는 **서울 러너 또는 로컬**에서 | 자기 자신을 만드는 러너는 아직 없습니다(`global/bootstrap`·`global/cicd` 와 같은 종류의 닭과 달걀) |
