# 런북 — 드릴 레코드(`dr-drill.`) 전환과 되돌리기

**훈련 단계**: 1부 8단계(`4-edge` 첫 실행) · **2부 6단계(⑤ 드릴 레코드 전환)** · 뒷정리 6.3 #5
**관련**: `DR테스트_계획서_도쿄리전전환훈련_최종본_2026-10-27.md` 2.2 ⑤ · 8.1

---

## 0. 무엇을 하는 런북인가

훈련에서 **운영 도메인을 건드리지 않고** `dr-drill.aquasentinel.cloud` 한 호스트만 서울 → 도쿄로 넘긴다.

🔴 **서울 ALB·파드·노드를 죽이지 않는다.** 드릴 전용 Route53 헬스체크의 **판정만 뒤집는다**(`invert_healthcheck`). 그래서 판정 창 목표 #1·#2·#3 이 떨어지지 않는다.

```
평소   dr-drill. ──> 서울 ALB   (운영 3개와 같은 ALB, 다른 헬스체크)
훈련   스위치 true ──> 90초 뒤 ──> 도쿄 ALB
```

## 1. 기준값

| | 값 |
|---|---|
| 호스트 | `dr-drill.aquasentinel.cloud` |
| Hosted Zone | `Z04047191I2SWBLU7U7D` (`aquasentinel.cloud`) |
| 드릴 헬스체크 이름 | `aquasentinel-dev-drill-healthcheck` (태그 `Role=dr-drill`) |
| 전환 소요 | **약 90초**(`request_interval` 30초 × `failure_threshold` 3) + ALIAS 캐시 최대 60초 |
| 🔴 손대지 않는 것 | `aquasentinel-dev-readyz-healthcheck`(#1 판정) · `aquasentinel-dev-alb-healthcheck`(운영 failover) |

## 2. 전환 (서울 → 도쿄)

```bash
cd AWS/terraform/seoul/rebuild/4-edge
terraform init -backend-config=backend.hcl -reconfigure
terraform apply \
  -var tfstate_bucket=aquasentinel-tfstate-379937169195 \
  -var drill_health_check_inverted=true
```

**확인** — 90초 기다린 뒤:

```bash
dig +short dr-drill.aquasentinel.cloud
# 도쿄 ALB(ap-northeast-1) 주소가 나와야 한다
```

🔴 **운영 도메인이 그대로인지 같이 본다** — 이게 이 런북의 핵심 확인이다.

```bash
for h in aquasentinel.cloud auth.aquasentinel.cloud grafana.aquasentinel.cloud; do
  printf '%-32s ' "$h"; dig +short "$h" | head -1
done
# 셋 다 ap-northeast-2(서울) 주소여야 한다
```

## 3. 되돌리기

```bash
terraform apply \
  -var tfstate_bucket=aquasentinel-tfstate-379937169195 \
  -var drill_health_check_inverted=false
```

90초 뒤 `dig +short dr-drill.aquasentinel.cloud` 가 다시 서울 주소.

## 4. 완전히 지우기 (뒷정리 6.3 #5)

`seoul/rebuild/4-edge/main.tf` 의 `drill_hostnames` 를 `[]` 로 두고 apply 하면 레코드와 헬스체크가 **둘 다** 사라진다. 도쿄 쪽은 `rebuild/*` destroy 로 같이 없어진다.

## 5. 하지 않는 것

| | 왜 |
|---|---|
| 운영 헬스체크를 뒤집기 | 🔴 운영 도메인 3개가 **전부** 넘어간다. 판정 창 목표가 깨진다 |
| `drill_hostnames` 에 `""`(apex) 넣기 | 운영 apex 레코드와 같은 이름·같은 `set_identifier` 가 되어 서로 덮어쓴다. 모듈 `validation` 이 막는다 |
| 스위치를 `true` 로 커밋·머지 | 머지 즉시 전환이 걸린다. 코드 기본값은 **항상 `false`** |
| 도쿄에서 뒤집기 | 도쿄는 `enable_health_check = false` 라 드릴 헬스체크가 **없다**. 뒤집는 쪽은 언제나 서울 PRIMARY |

## 6. 선행 조건

| | |
|---|---|
| 서울 `4-edge` apply 1회 | 드릴 레코드·헬스체크 생성. 🔴 **판정 창 안 운영 변경으로 기록**(계획서 8.2) |
| 도쿄 `4-edge` apply | 1부 8단계 · 2부 7-1단계 — SECONDARY 레코드. 없으면 넘어갈 대상이 없다. 🔴 **훈련에서는 `-var 'failover_hostnames=[]'`** — 안 주면 운영 도메인 SECONDARY 3개가 같이 생겨 서울이 흔들릴 때 진짜 사용자가 도쿄로 간다(2026-10-28) |
| 🔴 `dr-drill.` 로 화면이 뜨는 것은 **별개** | 웹 HTTPRoute 에 호스트가 없으면 Gateway 404 다. 결정 ②로 **도쿄에만** 넣는다(계획서 7장 #9) |
